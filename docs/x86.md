# x86-64 machine models

Silmaril has several x86-64 user-mode models. This page says how they relate, which
one to state a function contract on, and which lemmas move proofs between them.
All instruction semantics are handwritten from the Intel SDM. They are **trusted**:
nothing here proves that they match hardware.

**Short answer.** State x86 function contracts on **`Open9.isa`**, the open machine
over `Ext9`, as a `FnContract Open9.isa`. Code that only uses `Ext`/`Ext8` forms can
be proved on `Open.isa` and moved up with `FnContract.toOpen9`. Code that uses the string
forms `movsb`, `rep movsq` or `rep stosq` (musl's `memcpy` and `memset`) is proved on
**`Str9.isa`**, and every `Open9` contract moves there with `FnContract.toStr9`.

## The tower

Every machine below works on `Silmaril.X86.MState` (core registers and flags plus a
`Process.Memory`). The open machines are `SegVC.Isa MState` instances, so the segment
VC generator `Silmaril.X86.SegVC` and the contracts `Silmaril.X86.FnContract` apply.

```
X86.MState.step ⊂ Ext ⊂ Ext8 ⊂ Ext9      sentinel machines: step exit, Returns exit
                         │      │
                        Open ⊑ Open9 ⊑ Str9   open machines: SegVC.Isa MState (default: Open9)
```

| model | module | adds |
|---|---|---|
| `Silmaril.X86.Ext` | `Silmaril.X86.Ext.*` | the integer ISA: `mov`, ALU, `lea`, `jcc`, `call`/`ret`, `push`/`pop`, `cmov`, `div`/`mul`, … |
| `Silmaril.X86.Ext8` | `Silmaril.X86.Ext8.Basic` | 8-bit forms: ALU, `test`, shifts, `mov`, `movzx`/`movsx`, `setcc` on all byte registers (`Instr = base ∣ new`) |
| `Silmaril.X86.Ext9` | `Silmaril.X86.Ext9.{Defs,Thms}` | three- and one-operand `imul`, `bsf`/`bsr`, `adc`/`sbb`, `call`/`jmp r/m64` (and `notrack jmp`), `push imm`, 16-bit ALU/`cmp`/`test`, `test imm`, `bt r,r`, `rep ret` (`Instr = ext8 ∣ new`) |
| `Silmaril.X86.Open` | `Silmaril.X86.Open.{Defs,Thms}` | the **open machine** over `Ext8`: no designated exit, every `ret` is a pop and jump; `Open.isa` |
| **`Silmaril.X86.Open9`** | `Silmaril.X86.Open9.{Defs,Thms}` | the open machine over `Ext9`: `Open.step`, plus the `Ext9` forms on bytes `Ext8` does not decode; `Open9.isa` |
| `Silmaril.X86.Str9` | `Silmaril.X86.Str9.{Defs,Thms}` | `Open9` plus three string forms on bytes `Ext8` and `Ext9` reject: `movsb` (`A4`), `rep movsq` (`F3 48 A5`), `rep stosq` (`F3 48 AB`), one element per step, DF clear (`Instr = ext9 ∣ str`); `Str9.isa` |

The **sentinel machines** `Ext.step exit`, `Ext8.step exit` and `Ext9.step exit` report
the `ret` that pops the designated address `exit` as `returned`, so a run of
`stepOpt exit` ends there (`Returns exit`). A caller and its callee use different
exits, so their runs disagree about which `ret` ends a run. The **open machines** have
no exit: every `ret` is an ordinary step, and having returned is a property of a state
(`Open.Returned`, `FnContract.AbiReturn`). Function contracts therefore live on the
open machines.

Each `Ext9` decode tries `Ext8.decode` first, so every `Ext8` decode, execution, step
and returning run is unchanged (`Ext9.decode_of_ext8`, `Ext9.exec_ext8`,
`Ext9.step_eq_of_ne_undecodable`, `Ext9.returns_of_ext8`). Its decoder rejects rather
than misreads what it does not model (the FS override, `F2`, `F3` except on `C3`, `66`
with REX.W). `Ext9/Defs.lean` documents each form and the choices where the SDM leaves
results undefined (BSF/BSR of zero, ADC/SBB with an undefined carry, BT's ZF).

Separate from this tower: the feature-parametric machine `Silmaril.X86.Features`
(vector, mask, MXCSR and x87 state), the scalar FP model `Silmaril.X86.Float`, and the
Linux process machines `Silmaril.Apps.Sha256sum.X86Sys` (`Isa.sys`, `Isa.sys8`).

## Machine extensions

`SegVC.Isa.Extends I J` (`Silmaril.X86.Extends.Defs`) says that `J` extends `I`: along a
lawful lens `view : τ → σ`, `put : τ → σ → τ`, every step of `I` on the view is a step
of `J` that changes only the view. Core, memory, update and liveness are those of the
view. With equal states the lens is the identity (`Extends.ofStep`); a machine with more
state (an XMM file, for instance) uses `view` to forget it. It is the one mechanism for
moving proofs up the tower:

| lemma | statement |
|---|---|
| `Isa.Extends.run`, `Isa.Extends.reaches` | an `I` run from the view of `x` is a `J` run from `x`, ending at `put x t` |
| `Isa.Extends.trans`, `Isa.Extends.refl` | extensions compose |
| `FnContract.Spec.Total.lift`, `FnContract.lift` | a contract on `I` is a contract on `J`, for the spec read through `view` (`Spec.comap`) |
| `FnContract.RunsIn.lift` | an `I` run inside `P` from the view of `x` is a `J` run inside `P ∘ view` |
| `FnContract.Spec.TotalIn.lift` | a `TotalIn` spec on `I` is `TotalIn` on `J`, with the run predicate read through `view` |
| `FnContract.Spec.Strict.lift`, `FnContract.Spec.StrictBelow.lift`, `FnContract.Strict.lift` | a strict (first-return) spec or contract on `I` is one on `J` (`Returned` and `Below` read only core and memory: `Returned.lift_iff`, `Below.lift_iff`) |

## Transfer lemmas

Contracts move **up**. There is no lemma from `Open9` down to `Open`: `Open` has no step
where `Ext9` adds one.

| from → to | step / run | contract |
|---|---|---|
| `Ext8.step exit` → `Open` | `Open.step_of_ext8_stepOpt`, `Open.step_of_ext8_returned`, `Open.reaches_of_ext8`, `Open.returns_open`, `Open.returns_open_ext`; back: `Open.ext8_of_step` | `Open.total_of_returns`, `Open.contractOfReturns` |
| `Ext8` → `Ext9` (sentinel) | `Ext9.stepOpt_of_ext8`, `Ext9.run_of_ext8`, `Ext9.returns_of_ext8`, `Ext9.returns_of_ext` | - |
| `Ext9.step exit` → `Open9` | `Open9.step_of_ext9_stepOpt`, `Open9.returns_open9` | `Open9.total_of_returns`, `Open9.contractOfReturns` |
| `Open` → `Open9` | `Open9.extendsOpen : Open.isa.Extends Open9.isa`, `Open9.step_of_open`, `Open9.run_of_open`, `Open9.reaches_of_open` | `FnContract.Spec.Total.toOpen9`, `FnContract.toOpen9`; strict: `FnContract.Spec.Strict.toOpen9`, `FnContract.Spec.StrictBelow.toOpen9`, `FnContract.Strict.toOpen9` |
| segment VC → run | `SegVC9.seg_runsIn`, `SegVC9.seg_runsIn9`: a segment `wpN` with exits is a `FnContract.RunsIn` run inside the code | with `FnContract.Spec.strict_of_inCode`, a strict spec |
| `Open9` → `Str9` | `Str9.extendsOpen9 : Open9.isa.Extends Str9.isa`, `Str9.step_of_open9`, `Str9.run_of_open9`, `Str9.reaches_of_open9`; `Str9.extendsOpen` (from `Open`, by `trans`) | `FnContract.Spec.Total.toStr9`, `FnContract.toStr9` (`FnContract.lift`) |

On bytes that `Ext8` fetches (anything but `undecodable`), `Open9.step` **is**
`Open.step` (`Open9.step_eq_open`). An `Open` proof followed by `toOpen9` is therefore a
complete `Open9` proof, and a callee proved on `Open` can be used by an `Open9` caller.
Likewise, wherever `Ext8` or `Ext9` fetches a form, `Str9.step` **is** `Open9.step`
(`Str9.step_eq_open9`); `Str9.step_cases` says every other `Str9` step is a string form.

## Which machine to use

| situation | use |
|---|---|
| a new x86 function contract | `FnContract Open9.isa` |
| code with only `Ext`/`Ext8` forms, proved with `Ext8.Returns` runs | `Open.contractOfReturns`, then `FnContract.toOpen9` |
| code with `Ext9` forms, proved with `Ext9.Returns` runs | `Open9.contractOfReturns` |
| code with `movsb`, `rep movsq` or `rep stosq` | `FnContract Str9.isa`; string steps by `Str9.step_of_listed_str` and the run lemmas `Str9.rep_movsq_copy`, `Str9.rep_stosq_fill`; callees without string forms by `FnContract.toStr9` |
| a segment proof over a listing | `SegVC.sound` on `Open9.isa` (the listing is checked against `Open9.decode` by `decide`) |
| a callee inside a segment proof | `FnContract.toCall` |
| splitting a code region into functions | `Partition.check2` (or `Partition.Shard` for large regions), see Partitions |
| vector, mask or x87 state | `Silmaril.X86.Features` (not connected to this tower) |

The `seg_vc` tactic unfolds executors built from `Ext.exec` (and `seg_vc8` from
`Ext8.exec`). On `Open9.isa`, use `seg_vc9` (`Silmaril.X86.SegVC9.Thms`): `seg_vc`'s
lemma set with the `Ext9` dispatch lemmas (`exec9_base`, `exec9_ext8new`, `exec9_new`,
`exec9_imulI_reg`), the `Open9.isa` projections, `push` with an opaque successor memory,
and `mk_write'` (a propositional `mk_write`, which keeps the kernel from unfolding 64-bit
literals). It does not unfold `nextAt`: pass `nextAt` or the `nextAt_cut`/`nextAt_stop`/
`nextAt_cont` equations. Other new forms go through `exec9_new` and their `Ext9.execNew`
case. `seg_vc9_var` is the same tactic over precomputed simp sets (`seg_vc9_var`, and a
listing's lookups added locally to `seg_vc9_listing`), with equation lemmas for segment
lemmas whose offsets and budget are variables (`wpN_one`, `wpN_one_cont`, `wpN_budget`).
`Silmaril.X86.SegVC9.Examples` proves an `imul`/`mov` segment with `seg_vc9` and turns it
into a run inside the code.

## Contracts

`FnContract I` (`Silmaril.X86.FnContract.{Defs,Thms}`) is a total System V contract over
any `I : SegVC.Isa σ`: a spec (`entry`, write `footprint`, `post`) and `total`. From
every live entry state with `AbiEntry` (`rsp ≡ 8 mod 16`, a readable return address) and
`entry`, the machine reaches a state with `Spec.Result`. Only core and memory changed,
`rip` is the return address, `rsp` is popped, the callee-saved registers are restored,
memory changed only inside the footprint, and `post` holds. `Spec.Total` is angelic: it
promises some returned state, not the first one. Refinement and frames are `mono`,
`frame`, `Result.readBytes` and `Result.reg`; `toCall` makes a contract a
`SegVC.Call`.

**First return.** On an open machine a run continues into the caller after the return,
so `Spec.Total` alone does not say which returned state is meant. `RunsIn I P s t` is a
run whose every step is taken from a state satisfying `P`. `Spec.TotalIn I S P` is
`Spec.Total` with the run inside `P s`. `Spec.Strict` is a `TotalIn` that passes no
`Returned` state before its last step, so its result is the first return
(`Spec.Strict.firstReturn`, unique by `firstReturn_unique`). `Spec.StrictBelow` adds the
stack-depth invariant `Below`, the form that composes across calls. `Spec.Strict.total`
recovers `Spec.Total`. A run inside the code (`InCode`) with the return address outside
it (`RetOutside`) is strict (`Spec.strict_of_inCode`). `FnContract.Strict` is a contract
with a strict proof.

## Separation logic

`Silmaril.X86.Sep` is a shallow separation logic over the machine states of this tower: an
assertion (`SProp`) is a predicate on partial states (`Frag`), and there is no step index,
ghost state or Iris. It works on any `SegVC.Isa σ`, through the fragment `frag I s` of a
state's core and memory.

| module | contents |
|---|---|
| `Silmaril.X86.Sep.{Defs,Thms}` | locations (registers, `rip`, flags, bytes with their permissions, the mapping list; not the FS base), `sep` (`∗`), `emp`, `spure` (`⌜φ⌝`), `sexists`, `sand`, `wand`, `Entails` (`⊢ₛ`); atoms `regPt`, `ripPt`, `flagsPt`, `regionsPt`, `bytePt`/`bytePtRO`/`codeByte`, `bytesPt`, `codePt`, `wordPt`, `byteAny`/`blockAny`. Laws: `sep_assoc`, `sep_comm`, `emp_sep` (as `Std` instances, so `ac_rfl` rearranges `∗`), `sep_mono`, `wand_intro`/`wand_elim`, `bytesAt_append`, `blockAny_add`; atoms to `Memory.readBytes`/`fetchBytes`/`Permitted` |
| `Silmaril.X86.Sep.Extra.{Defs,Thms}` | `sor` and `strue` (garbage) with their laws |
| `Silmaril.X86.Sep.Spec.{Defs,Thms}` | `Triple I P Q`: from every live state whose fragment splits as `P ∗ F`, for every frame `F`, `I` reaches one that splits as `Q ∗ F`; `SPEC I C P Q` with code `C` returned unchanged. Rules `frame`, `conseq`, `trans`, `sexists`, `spure`; `of_local` (a triple from a run), `run` (a run from a triple); `Triple.lift` along `Isa.Extends` |
| `Silmaril.X86.Safe.{Defs,Thms}` | step-indexed `SafeN`, `STriple`, `Progress`, with frame, consequence, sequencing (`progress_seq`: one step pays for the index), `of_triple`, and `lift` along `Isa.Extends` |
| `Silmaril.X86.Sep.SysV.{Defs,Thms}` | `FnSpec` (logical arguments, argument registers, stack budget, pre/post) and the System V template `SysVPre`/`SysVPost`; `FnSpec.Sat I C entry S`; `call_step`, `ret_step`, `push_step`, `pop_step`; `call_rule`; `calleeSaved_by_frame`; refinement `FnSpec.Sub`; `FnSpec.satWith_of_runs`; contracts both ways (`sat_of_fnContract`, `Sat.toFnContract` on a `Flat` machine) |
| `Silmaril.X86.Sep.Alloc.{Defs,Thms}` | a `malloc`/`free`/`calloc`/`realloc` interface for clients, with the never-allocating allocator as a non-vacuity witness |
| `Silmaril.X86.Sep.AllocS.{Defs,Thms}` | the availability layer: `IfaceS` (an abstract allocator state and `avail s n`, a request that must succeed), `mallocSpecS`, and the heap-dependent refinement `FnSpec.SubH` with `SubH.satWith`; `mallocSpecS_sat_toIface` (a strong `malloc` is a loose one), `mallocS_post_avail` |
| `Silmaril.X86.Sep.Insn.{Defs,Thms}` | single-instruction triples for `X86.Ext` forms (`mov` to/from `disp(%base)`, `lea`, `xor`, 32-bit `mov`, `mov $imm32`, `test`, `jcc rel8`), and `insn_triple`/`open_of_ext` with fragment helpers for building more |
| `Silmaril.X86.Sep.Ind.{Defs,Thms}` | indirect `call`/`jmp` (`FF /2`, `FF /4`, register and `disp8(%base)` forms): encoders, decoding through `Open9.decode`, and the step laws as `Progress` on every `I` with `Open9.isa.Extends I` (`callR_progress`, `callM_progress`, `jmpR_progress`, `jmpM_progress`), with non-vacuity witnesses |
| `Silmaril.X86.Safe.Exc.{Defs,Thms}` | two-exit triples for non-local exits: continuations `Cont`, `AtCont`, the exceptional exit `Exc`, `STripleX I n P Q k E` (frame leaked on the exceptional exit, survivor frame kept); `frameF`, `frameG`, `seq`, `lift`, `xcall_rule`, and `catch_rule`, which seals the exceptional exit into an ordinary `STriple` |
| `Silmaril.X86.Sep.JmpBuf.{Defs,Thms}` | the System V `jmp_buf` (`jbPt`, `jbAny`) and a 43-byte `setjmp`/41-byte `longjmp`: `setjmp_triple` (a total triple on every `I` extending `Open.isa`) and `longjmp_triple` (an exceptional-only `STripleX` on every `I` extending `Open9.isa`) |
| `Silmaril.X86.Sep.Examples` | `push rax; pop rbx` (a store and a load) as a `SPEC`, on `Open9.isa`, framed with a caller's buffer |
| `Silmaril.X86.Sep.JmpBuf.Catch.{Defs,Thms}` | a worked `setjmp`/`longjmp` example: `catch → throw2 → throw1 → longjmp(jb, 0)` (122 bytes), `catch_test` (`catch` returns `-1` through `catch_rule`, at every index), and a concrete state that meets its precondition (`catchPre_m0`, `catch_m0`) |

**Machines.** Instruction triples are proved on `Open.isa` and stated on every `I` with
`Open.isa.Extends I` (pass `Isa.Extends.refl _`, `Open9.extendsOpen` or `Str9.extendsOpen`);
the `Ext9` forms (indirect `call`/`jmp`, so `longjmp` and the catch example) on every `I`
with `Open9.isa.Extends I`. Every triple, step-indexed triple, two-exit triple and
`FnSpec.Sat` moves up an extension (`Triple.lift`, `STriple.lift`, `STripleX.lift`,
`FnSpec.Sat.lift`); this replaces per-machine refinement classes and step-law classes. A machine
with more state than core and memory keeps the rest out of the logic: a triple says nothing
about it.

**Contracts.** A `Triple` is angelic, as `FnContract.Spec.Total` is: it promises some
reachable state, not the first one. So `FnSpec.Sat.toFnContract` gives a `FnContract`
(`Spec.Total`), not a `FnContract.Strict`; it needs `Flat I` (the state is its core and
memory: `flat_open`, `flat_open9`, `flat_str9`) for `Result.silent`, and a precondition that
owns neither the mapping list nor a callee-saved register. In the other direction,
`FnSpec.sat_of_fnContract` takes any `FnContract` (for a strict one, its `toFnContract`).
## Partitions
`Silmaril.X86.Partition` checks a proposed split of a code region into functions, as
compilers lay them out: a function is a **set of byte ranges** (gcc's `f.cold` in
`.text.unlikely` is part of `f`), it may leave by a tail call or never return, local
functions may carry a compiler-chosen convention, and the region may contain instructions
outside the model. The proposal (`Proposal`: functions with entry, `Convention`, `exported`
and `noreturn` flags; a `layout` of code and padding slots; declared tail-call sites; declared
unmodelled instructions) is untrusted; `check2 r p fuel` accepts it (`none`) or names the
offending address (`Reject`). It decodes the region with the `Ext8` listing decoder
`decodeAt`, checks that the layout tiles the region, that padding is NOPs, and that every
edge of every owned instruction stays in its function, enters a function by a call, or is a
declared tail call. A declared unmodelled instruction must be one `decodeAt` rejects.
The soundness theorems (`Partition/Thms.lean`) hold for any machine that **executes the
listing** (`Executes`: a step from a listed, modelled instruction in a memory holding the
region is that instruction's execution). `executes_ext8`, `executes_open` and
`executes_open9` prove it for `Ext8.stepOpt exit`, `Open.step` and `Open9.step`.
| theorem | statement |
| `sound_step`, `sound_step_open9`, `sound_step_of` | one step from an owned instruction of `i` stays in `i`, or was a call or a declared tail call and enters a function entry, or was a `ret` |
| `sound_run` | a run of internal steps (`InternalRun`: no call, `ret`, tail call or unmodelled instruction) never leaves the function |
| `return_site` | after a call to a function not declared `noreturn`, the next instruction is the caller's |
| `noreturn_no_ret`, `noreturn_modelled`, `noreturn_tailcall` | a `noreturn` function has no `ret`, no unmodelled instruction, and tail-calls only `noreturn` functions |
| `entry`, `exported_abi`, `listed`, `slot`, `layout` | entries are owned, exported functions carry an ABI tag, the listing is the model's decoding, the layout tiles the region |
Not claimed: anything about the successor of an unmodelled instruction, where a `ret` goes
(a function contract's business), or the `inferred` conventions and `exported` flags, which
are recorded data.
**Sharding.** One `decide` of `check2` over a large region is slow in the kernel.
`Partition.Shard` splits it: an untrusted `Cert` cuts the region into pieces inside layout
slots and gives each function's instruction addresses as a bitmap. `checkGlobal` (no
decoding) checks the layout, the pieces and the bitmaps; `checkPiece` decodes one piece from
its bytes plus at most 15 bytes of lookahead. `accepted_of_shards` turns the global check,
one theorem per piece (`Below`) and one comparison of the piece bytes with the region into
`check2 r p fuel = none`, so the pieces can be proved in separate modules and built in
parallel. `bytesNat! "…"` writes piece bytes cheaply. `Partition/Examples.lean` checks a
function with a cold range both ways and takes one `Open9` step from it.

## Evidence

- `Str9/Defs.lean` documents the string forms and their choices: one element per step
  (the interrupt points of a `rep` instruction), DF clear (the state has no direction flag;
  System V requires DF clear at calls and returns), a faulting element leaves the state of
  the last completed one, and overlapping copies are read element by element. `cmps`,
  `scas`, `lods`, other prefixes and other operand sizes are not decoded. `Str9/Thms.lean`
  ends with kernel-checked decoding vectors (the three encodings; rejected prefixes and
  string instructions) and semantic vectors (pointer and `rcx` updates, faults).
- `Ext9/Thms.lean` ends with kernel-checked (`decide`) decoding vectors (bytes emitted by
  gcc 13.3 at `-O2`, accepted and rejected forms) and semantic vectors (BSR/BSF,
  ADC/SBB flags, one-operand IMUL overflow).
- The `Ext9` semantics have been differentially tested against x86-64 hosts (Intel
  only) outside this repository. That is evidence, not proof, and the test harness is
  not part of the library.
- Build the slice with
  `lake build --wfail Silmaril.X86.Open9.Thms Silmaril.X86.FnContract.Thms
  Silmaril.X86.SegVC9.Thms Silmaril.X86.SegVC9.Examples Silmaril.X86.Str9.Thms`, and the
  separation logic with `lake build --wfail Silmaril.X86.Sep.SysV.Thms
  Silmaril.X86.Sep.Alloc.Thms Silmaril.X86.Sep.AllocS.Thms Silmaril.X86.Sep.Examples
  Silmaril.X86.Safe.Thms Silmaril.X86.Safe.Exc.Thms Silmaril.X86.Sep.Insn.Thms
  Silmaril.X86.Sep.Ind.Thms Silmaril.X86.Sep.JmpBuf.Thms Silmaril.X86.Sep.JmpBuf.Catch.Thms`.
  Silmaril.X86.SegVC9.Thms Silmaril.X86.SegVC9.Examples Silmaril.X86.Partition.Examples`.
