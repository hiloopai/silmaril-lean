# x86 memory models and concurrency

This note maps the memory-model and concurrency development in `Silmaril.X86.MemoryModel`,
`Silmaril.X86.Litmus` and `Silmaril.X86.Concurrency`: what each layer states, what is proved,
and what is only stated. Everything below is proved with the standard axioms unless it is
called a `Task`; open goals are frozen as `def Task.x : Prop` and every theorem that needs one
takes it as a hypothesis. Instruction semantics are those of [x86.md](x86.md) and are trusted.

## Layers

```
litmus corpus (tools/litmus-x86)         C programs (examples/litmus-c, pinned objects)
        │ bytes                                   │ bytes
        ▼                                         ▼
X86.Litmus  event extraction from bytes  ──►  Concurrency.Cir.Tv*  translation validation
        │ traces                                  │ CIR programs
        ▼                                         ▼
MemoryModel.Axiomatic / Xl / Tso / OpAx  ◄──  Concurrency.Cir     events, behaviours
        SC ⊑ TSO ⊑ XL, op-TSO = ax-TSO             │
                                                  ▼
                                   Cir.Csl  CSL, DRF-SC on store buffers (TSO, XL)
                                   Cir.Mutex / Prim / Chan / Rc  verified primitives
                                   Cir.Proc  threads, clone and futex at process level
```

## Memory models (`Silmaril.X86.MemoryModel`)

| module | contents |
|---|---|
| `Axiomatic.{Defs,Thms}` | herd-style candidate executions over byte units, `Exec.Sc`, `Exec.Tso` (a transcription of herd's `x86tso.cat`), acyclicity facts |
| `Xl.{Defs,Thms}` | **XL**, a loose x86 model: TSO on tame accesses, non-temporal and string stores weakly ordered, tearable accesses split per byte; `xl_iff_tso_of_tame`, SC ⊑ TSO ⊑ XL |
| `Tso.{Defs,Thms}` | operational store-buffer TSO: a word-granular model (`Silmaril.Memory.TSO`, in `Silmaril/Raw/X86/MemoryModel`) and a byte-granular, mixed-size one (`XState`, `XStep`, `XFlush`) |
| `OpAx.{Defs,Thms}` | the byte store-buffer machine against axiomatic TSO in both directions: `run_explains_tso` (every run is explained by a TSO execution) and `axToOp_holds` (every TSO execution of a well-formed program is reached by a run); operational TSO is included in XL |
| `Litmus.{Defs,Thms}` | the litmus data shapes (`Test`, locations, threads with bytes and events, outcome conditions, `Verdict`) |
| `Litmus.Corpus.{Defs,Thms}` | the corpus: 68 x86 tests with TSO verdicts (herdtools7 catalogue and test suite, tests from Owens, Sarkar and Sewell, and hand-written tests), generated by `tools/litmus-x86` |
| `Litmus.Models`, `Litmus.Verdicts` | final states under operational TSO and axiomatic SC/TSO/XL over the extracted traces (`AxReach`, `OpReach`, `axReach_mono`), and every recorded verdict checked by kernel `decide` |
| `Litmus.Closure`, `Litmus.Weak` | the value-domain closure of the trace sets; traces over the `Weak9` machine (`movnti`, `rep stos`) |

## Litmus extraction (`Silmaril.X86.Litmus`)

`Test` and `Extract` turn a thread's **bytes** into memory actions with the decoder of the
atomic machine `Atomic9`; `extract_sound` says every extracted trace is a real run.
`Complete` and `Domain` give completeness of the extraction and its dependence on the value
domain. `WeakExtract` does the same over `Weak9` (`Silmaril.X86.Weak9`: `Atomic9` with
`movnti` and string stores). `Silmaril.X86.Atomic9.Thms` has the decoder and step theorems
of the atomic machine that these proofs need.

## CIR (`Silmaril.X86.Concurrency.Cir`)

CIR is a small concurrency IR: loads, stores and read-modify-writes with C11 modes, fences,
futex wait/wake, spawn/join and `local` blocks, lowered to the same events as the machine code.

* `Cir.{Defs,Thms}`, `Cir.Domain`: syntax, event semantics, `BehavIn P dom M`, `sc_le_tso`,
  `tso_le_xl`, and domain closure (`cirDomain`).
* `Cir.Seq`, `Concurrency.Lift`, `Lift.Process`: the single-threaded lift. One thread cannot
  tell `SC ⊑ M ⊑ XL` from sequential replay, so every total `Open`/`Open9` function contract
  holds under every such model (`totalUnder_of`, zlib's checksums as examples), and a
  process-safe LPS execution is single-threaded and reads the same under `M`.
* `Cir.Sync`, `Cir.Futex`, `Cir.Futex.Live`: spawn/join edges, futex semantics, lost
  wake-ups, liveness under fairness (stated).
* `Cir.Tv`, `Cir.TvCfg`, `Cir.TvCfg.Fx`, `Cir.Tv.{Spin,Sys,Marked}`: **translation validation**
  of x86 threads into CIR. An untrusted proposer (`tools/litmus-x86`) emits a certificate per
  thread and a checker in Lean accepts it; the checker is proved sound (`tvRun_real`,
  `tvCfg_real`, `tvFx_real`): every run of the bytes is a run of the CIR program. The
  corpora (`Tv.Corpus`, `Tv.CSpawn`, `Tv.CFutex`, `Tv.Chan`, `C11.Corpus`) are generated and
  checked by kernel `decide`; `Tv.Mutants` and `C11.Mutants` check that mutated bytes or
  certificates are rejected.
* `Cir.Localize`: an owned fragment of a thread becomes a `local` block (`cirLocalize`).
* `Concurrency.Bridge`: real `Atomic9` runs under the byte TSO pool (`Silmaril.X86.Pool`) are
  CIR runs (`tsoRunCir_holds`), with calls into validated function bodies (`Bridge.Crit`).
* `Cir.Rc11`, `Cir.C11`: RC11 on CIR and the C11 litmus programs of `examples/litmus-c`
  against their compiled objects.
* `Cir.Robust`, `Cir.Refute`, `Cir.Scale`, `Cir.Carve`: a finite-state explorer, a
  TSO-robustness checker, refutation by forced cycles, and `N`-thread clients.

## CSL and DRF (`Cir.Csl`)

`Cir.Csl.Defs` defines a CIR-native SC machine (`TStep`, `ScStep`), store-buffer machines
`OStep .tso` and `OStep .xl`, concurrent separation logic safety (`Safe`), the global
invariant `GInv` and data races (`Race`). `Cir.Csl.Thms` proves:

* `csl_sc`, `no_race`: CSL-certified programs keep the invariant and are race-free under SC;
* `drf_sc`, `drf_sc_drained`, `csl_buffered`: their TSO and XL store-buffer runs abstract to
  SC runs (DRF-SC for buffered models);
* `cirXlOpAx_holds`: every axiomatic-XL behaviour of a uniform, CSL-certified, spawn-free
  program is reached by the XL store-buffer machine, hence `drf_behav`.

`Cir.Csl.Rel` adds a release rule for plain `mov` unlocks on TSO (`SafeR`, `rel_tso`);
`Cir.Csl.Tame` shows that programs with only write-back stores have their XL runs among their
TSO runs (`reach_tso_of_wb`). `Silmaril.X86.Pool` proves the x86-level counterpart for a pool
of `Open` threads (`drfTso_holds`).

## Synchronisation primitives

All are C code in `examples/litmus-c`, compiled with pinned GCC and Clang, pinned as byte
literals (`*.Code.Defs`, regenerated by each directory's `pin.sh`) and translation-validated
into CIR, then verified in CIR under SC, TSO and XL.

| module | contents |
|---|---|
| `Cir.Mutex` | the `Mutex.Iface` interface (lock invariant, lock token, lock/unlock specs), `IfaceR`/`IfaceG` for release-store unlocks, clients and `link_any_mutex` |
| `Cir.Mutex.Futex` | Drepper's futex mutex (`fmutex`, "Futexes Are Tricky", mutex 2), validated from the compiled bytes |
| `Cir.Mutex.Xl`, `Cir.Mutex.Link` | the interfaces on every buffered model; a mutex linked as a library unit |
| `Cir.Prim` | spinlock, ticket lock, seqlock and an SPSC ring, with CSL specs, TSO/XL results and `spsc_not_robust` |
| `Cir.Chan`, `Cir.Rc`, `Cir.Pool`, `Cir.Fj`, `Cir.ParHash` | channels, reference counting, a worker pool, fork-join and parallel hashing |
| `Concurrency.Story` | the front door: verdicts in the words "allowed" and "not allowed" on bytes and on CIR, and a counter and a pipeline client |

## Processes (`Cir.Proc`)

`Cir.Proc` is a multithreaded process model over CIR labels. `PStep (I : UIsa) (base : Base)`
has a thread table (running, waiting on a futex word, exited; thread pointer; clear-child-tid
address), one shared SC heap, and a kernel layer for `clone` (with musl's and glibc's
`pthread_create` flag words), `futex` WAIT/WAKE, `exit` (clearing and waking
`clear_child_tid`), `exit_group`, `set_tid_address` and `gettid`; every other system call goes
to a single-threaded base relation. CIR's spawn/join and futex statements are lowered to these
system calls and `refines` proves the lowering correct; `solo_reach` shows that one thread
without `clone` or `futex` is the single-threaded machine. `Cir.Proc.Lps` relates the shared
arms to LPS (`Silmaril.Process.LPS`) through `Silmaril.Process.LpsBridge`, a bridge from the
open x86 machine to LPS.

## Tools

* `tools/litmus-x86`: parses herdtools7 `.litmus` files, assembles each thread with GNU `as`,
  checks SC/TSO verdicts with an exhaustive checker, emits the Lean corpus, ingests the
  compiled C programs and proposes translation-validation certificates. Its `--check` modes
  regenerate every generated module in memory and fail unless the committed files match.
* `tools/litmus-run`: runs the corpus's bytes natively and checks observed outcomes against
  the model-allowed sets.

## Not included

* No fairness or liveness theorem beyond `Cir.Futex.Live`'s statement; no progress for
  spin-with-yield loops.
* The process model's memory is SC; weak memory is handled at the CIR level, where every
  system call is a full barrier.
* The single-threaded lift's ladder example on a full libmini client executable is not
  included.
