# The per-part ELF reader and the explorer's ELF tab

Every part of a pinned ELF file, checked by the kernel on the file's exact bytes, and shown in the
explorer with its bytes and an (unverified) disassembly.

## Statements

`Silmaril.Elf.Staged.Reader` (`Defs`, `Thms`; proofs in `Silmaril.Proofs.Elf.Staged.Reader`):

| name | meaning |
|---|---|
| `kread x` | the byte oracle of kernel bytes `x : KBytes` (`KBytes.readLE`) |
| `window ws r` | the reads of `r` restricted to the byte ranges `ws` |
| `PartIs F ws p v` | the ELF specification's reader `p` (`Parse.header`, `Parse.phdr o`, `Parse.shdr o`, `Parse.strAt`, `Parse.body`, `readLoader`, `readLayout`), run on the bytes of `F` **inside `ws` only**, returns `v` |
| `ZerosAt F o n` | the `n` bytes of `F` at `o` are zero |
| `sub_kbytes` | `x.wf → x.toByteArray = raw → Check.Sub (kread x) (blobOf ⟨raw⟩)`: kernel bytes answer as the raw file |
| `partIs_of_kbytes`, `zerosAt_of_kbytes` | a part of the raw file from one `decide +kernel` run on its kernel bytes |
| `PartIs.run`, `.layoutIs`, `.bodyIs`, `.loaderIs` | a part as a fact of the specification (`p.run (blobRead F) = some v`) and of the staged parse (`Silmaril.Elf.Staged`) |

`F` is `blobOf ⟨raw⟩` with `raw := include_bytes …`, and `x` is `kbytes_def K of_include raw`
(`Silmaril.Data.IncludeBytes.Kernel`), whose `K.toByteArray = raw` the kernel checks by comparing
chunk literals. So each part is a statement about the raw file. The windows are part of the
statement; `Silmaril.Elf.Staged.Reader.Examples` shows that a narrower window, another part's
window, a different claimed value, truncated or malformed files, ELFCLASS32 and big-endian files
are refused.

## Pinned files

`Silmaril.Elf.Staged.Pinned.{HelloGcc,HelloClang,Sha256sum}.{Bytes,Defs,Thms}`, generated by
`scripts/elf-reader/gen.sh` (`elf-staged emit-reader`) from the files of
[examples/elf](../../examples/elf/README.md): GNU coreutils 9.4 `sha256sum` (Ubuntu
9.4-3ubuntu6.3, 39,336 bytes) and hello world built by gcc (15,960 bytes) and clang (16,008
bytes). All three are dynamically linked against glibc. Each `loader` theorem states the
`PT_INTERP` interpreter (`/lib64/ld-linux-x86-64.so.2`) and the `DT_NEEDED` names
(`libc.so.6`, plus `libcrypto.so.3` for sha256sum). For each file, `Thms` has

* `header`, `phdr_i`, `shdr_i`, `name_i`, `body_i`, `loader`: one `PartIs` each, with the
  reader's exact footprint (computed by the emitter with `Parse.trace`) as windows;
* `pad_k`: one `ZerosAt` for each byte range that no section occupies and no part reads;
* `layoutPart`/`layout` (`LayoutIs F L`) and `parses : Parses F (L.assemble bodies ld)`,
  assembled from the parts by `Staged.parses_assemble` with no further run of the reader.

All the theorems of each file (125 or 126) use only `propext`, `Classical.choice` and `Quot.sound`; no native
evaluation. Measured with `lake env lean` (this includes about 3.5 s of imports per module):
`Sha256sum/Thms.lean` 6.9 s, `HelloGcc/Thms.lean` 6.1 s.

**Coverage** (from the theorems' windows, every byte of the file):

| file | decoded | checked zeros | raw | unknown |
|---|---|---|---|---|
| `gnu-sha256sum` (39,336 B) | 8,516 | 3,514 | 27,306 | 0 |
| `hello-gcc` (15,960 B) | 5,510 | 9,556 | 894 | 0 |
| `hello-clang` (16,008 B) | 5,494 | 9,661 | 853 | 0 |

*Decoded* bytes are read by a checked part: a theorem states the value parsed from them. *Raw*
bytes are **not parsed**. They lie in a range whose extent a checked theorem states, either a section
body kept as a byte range (for example `body_16 : PartIs F [] (Parse.body L.shs sh16)
(.progbits ⟨4192, 265⟩)` for hello-gcc's `.text`, read with an empty window) or a loaded
segment's file range (`phdr_i`). Nothing is stated about their contents beyond their being the
pinned file's bytes (`include_bytes`). They include code, `.rodata`, `.data`, `.eh_frame`, `.got`,
init/fini arrays, and string-table bytes that no part reads. **`unknown = 0`** means every byte
is in a checked part, a checked padding range, or a checked section or segment range. It does
**not** mean that every payload is decoded or understood.

**Not supported, listed rather than omitted:** ELFCLASS32, big-endian files, extended section
numbering and compressed sections. These are refused or read as no sections, never misread. Any
`e_machine` is accepted and recorded. The specification does not check alignment, overlap, or the
agreement of the section and loader views (`Silmaril.Elf.Lookup.DynConsistent`). Stripped files
have no `.symtab`, so only `.dynsym` is listed. A file with no section header table has no
sections, but its program headers and loader view are still read.

## Explorer

`tools/elf-pages` (`make pages`) writes `elf/index.json`, `elf/f/SLUG.json`, `elf/dis/SLUG.json`
and `elf/blob/SLUG.bin` next to the page. It imports the built `Thms` modules and **reads each
theorem's statement**. The part a theorem is about comes from the claimed constant's place in `L`,
`bodies` or `ld`, as defined in the environment. Its bytes come from the windows in the statement.
Its status and axioms come from `collectAxioms`. Theorem names and metadata are never used. The
tool re-runs each reader natively on its windows as a consistency check. It refuses any statement
of another form or about another file. `elf-pages --verify DIR` regenerates the data and compares
it. `scripts/elf-reader/test-pages.sh` checks that `--verify` rejects these edits to the data: a
moved window, a re-associated theorem, a widened coverage class, hidden axioms.

The ELF tab (`tools/silmaril-project/src/project/explore/views/elf.js`) has these pages:

* `#/elf`: the files, with theorem counts, axioms and coverage;
* `#/elf-file/SLUG`: identity and provenance (with an in-browser SHA-256), the coverage map, the
  header, program headers (file and memory extents, zero-filled memory), sections (segment,
  body kind, header, name and body theorems), the loader view, symbols and the unsupported list;
  `#/elf-file/SLUG/theorems` lists every theorem with its windows and axioms;
* `#/elf-bytes/SLUG/OFFSET[/LEN]`: 4 KiB pages of bytes coloured by coverage, with file offsets
  and virtual addresses. Selecting a byte shows its section, segment, and the theorems whose
  windows hold it. You can jump by offset or by virtual address;
* `#/elf-disasm/SLUG[/ADDRESS|SECTION]`: the committed GNU objdump listing, under a fixed
  **UNVERIFIED** warning. Each row's bytes are checked against the file. Addresses link to the
  byte view. No theorem is about the decoding.

The Assembly tab (`views/asm.js`) shows the assembly functions of `tools/elf-asm`
([elf-asm.md](elf-asm.md)). `elf-pages` copies the committed `examples/elf-asm/samples.json`
(`silmaril.elf.asm/1`) unchanged to `elf/asm.json`; its evidence is read from theorem statements
and checked by `elf-asm --check`, not re-derived here. `elf/asm-decls.json` gives the module and
source line of every declaration the file names, looked up in the checked environment.

* `#/asm`: every function record, one column per evidence dimension;
* `#/asm/FILE/NAME[/DECL]`: one record (`FILE` is the ELF tab's slug, else the file's base name; a
  chooser when several records of a file share a name). It shows the extent as given (`null` as
  unknown), the exact bytes, the objdump display lines (**display only, not checked**) beside each
  instruction model's decoding with its `DecodesAs` theorem, the references with their origin and
  grounding, and the evidence panel. The panel has one row per dimension: arch, bytes (segment,
  section, `CodeAt`), symbol, decodes (per model), lines tile, references grounded, contract
  (with its machine), and ABI conformance. Each row lists its declarations with source links,
  axioms and premises. A dimension with no theorem shows `none`. No row is inferred from another,
  and there is no overall status. `abiRef` is shown as metadata, not evidence. The data has no ABI
  conformance evidence yet ("no conformance row"); an optional `abi` array per function
  (`problemId`, `decl`, `abiId`, `mode`, `frame`, `status`) is the view's extension point for it.

The ELF tab's function table links a symbol to its assembly records (same file path and name),
and a record links back to the file and to the unverified objdump view.

Checks: `make elf-check`, run by `make check` when `elf-pages` is in scope, checks the pins,
regeneration and the tamper test. `tools/silmaril-project/tests/explore/elf.mjs` runs in the
Pages workflow's browser tests.

## Function tables

The **functions** tab of a file (`#/elf-funcs/SLUG`) lists every `STT_FUNC` and `STT_GNU_IFUNC`
entry of its symbol tables: `.symtab` when the file has one, otherwise `.dynsym` (all four library
files are stripped).

**What each row is backed by**
- **The symbol theorem.** `Pinned.*.Functions.sym_K_I : PartIs F ws (Parse.symbol strs o) sK_I`
  is entry `I` of section `K`, as the specification's reader reads it from the 24-byte record and
  the name bytes. Its windows are exactly those bytes, and it is checked by the kernel on kernel
  bytes. The symbol constants `sK_I` are the entries of the checked section body `bK`, so
  elf-pages reads a row's section and index from that definition.
- **Derived columns.** The version comes from the checked `.gnu.version` and
  `.gnu.version_d`/`_r` bodies: `@@` is the default version, `@` a non-default one. The segment,
  file offset and owning section come from the checked layout. Aliases are other function symbols
  with the same address. Overlaps are function ranges that intersect but differ.
- **Contract.** A row shows a contract only when a theorem's statement starts with
  `Silmaril.Elf.CodeAt F v code` at the row's address (`Pinned.ZlibChecksums.Contracts`). Every
  other row shows **no contract statement**.

**What a row does not say**
- A row is not a recovered function, and it says nothing about the System V ABI.
- When `st_size = 0`, the extent is **unknown**; it is not guessed.
- An IFUNC row is a **resolver**; the implementation is chosen at load time.
- An undefined row is an **import**.
- Nothing checks that the bytes in `[st_value, st_value + st_size)` are code, or one function.

**Contracts.** Only the four zlib functions with proofs in this repository have contracts:
`crc32_z`, `crc32`, `adler32_z` and `adler32` of `zlib-checksums`
(`Silmaril.X86.Ladder.ZlibChecksums`, System V entry contracts, `FnContract.Spec.Total` on
`Open`/`Open9`). `Pinned.ZlibChecksums.Contracts` ties each contract's code literal to the pinned
file itself, `CodeAt F v code`, by one kernel read on kernel bytes. The existing link,
`Silmaril.X86.Ladder.Pinned`, reads a `Blob` literal instead. Each theorem pairs the `CodeAt`
fact with the unchanged contract. The other libraries' functions (zlib `libz.so.1.3`, glibc 2.39
`libc.so.6` and `libm.so.6`) have no per-function contracts here: no new libm, allocator or other
semantic problems are added.

| file | function symbols | defined | imports | IFUNC | contracts | `Functions` check |
|---|---|---|---|---|---|---|
| `zlib-checksums` | 15 (`.symtab`) | 15 | 0 | 0 | 4 | 2.6 s |
| `zlib-libz` | 106 | 88 | 18 | 0 | 0 | |
| `glibc-libm` | 1,191 | 1,181 | 10 | 85 | 0 | 35 s |
| `glibc-libc` | 2,945 | 2,931 | 14 | 63 | 0 | 151 s |

`elf-pages --self-test` runs in `make elf-check`. It generates the pages once, verifies them, and
checks that `--verify` rejects each of these edits:
- a moved window;
- a re-associated theorem;
- a widened coverage class;
- hidden axioms;
- a function row given another row's theorem;
- a contract linked to another function;
- an assembly function's evidence kind changed, or a piece of its evidence dropped (`asm.json`).

Axioms are collected with one cache for all theorems, and checked against `Lean.collectAxioms` on
a sample.
