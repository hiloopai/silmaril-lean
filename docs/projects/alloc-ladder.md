# Allocators in static x86-64 executables: shapes and the toy-allocator ladder

Small freestanding C allocators (`examples/alloc-ladder`), each linked into a static non-PIE
x86-64 executable with the self-test driver and runtime of `examples/elf-ladder`, pinned byte for
byte, and proved against the separation-logic allocator interface `Silmaril.X86.Sep.AllocS` on
the loaded image.

| Piece | Module | What it gives |
| --- | --- | --- |
| Problem shapes | `Silmaril.Libc.Shapes.Alloc` | `silmaril.shapes.alloc.{safe,live,functional,functional_rel}` (and `model`), each with its `x86_open` instance; `Functional.live`, `Live.safe`, the client theorems `Safe.client` and `Live.serves` |
| Specifications | `Silmaril.Libc.X86Alloc.Spec` | loose, capacity (`mallocSpecL`), functional (`mallocSpecF`) and relational (`mallocSpecR`) specifications of `malloc`/`free`, reference and capacity models, simulations |
| Free-list segments | `Silmaril.Libc.X86Alloc.HdrSeg` | the list-segment predicate over block headers used by rungs 05 and 06 |
| Instruction lemmas | `Silmaril.Libc.X86Alloc.Insn` | per-instruction steps of the `Open` machine used by the rung proofs |
| Pinned executables | `Silmaril.Libc.X86Alloc.Pinned.*` | the nine `-O2` executables as `Blob` literals (generated by `examples/alloc-ladder/pin.sh`) |
| Rungs | `Silmaril.Libc.X86Alloc.Ladder.*` | per rung: the layout, the loader facts (`code_loaded`, `data_loaded`) and the machine proofs (`malloc_sat`, `free_sat`, `init`, and for the stronger strengths the simulation `sim`) |

| Rung | Allocator | Proved |
| --- | --- | --- |
| `01-never` | `malloc` returns NULL | safe |
| `02-bump` | bump over a 4096-byte arena | functional (hence live and safe) |
| `03-bump-align` | the same, 16-byte aligned | functional |
| `04-pool` | 64 blocks of 64 bytes, LIFO free list | functional |
| `05-firstfit` | first fit over headed blocks, splitting | live, safe, and `functional_rel` |
| `06-coalesce` | address-ordered list with coalescing | safe and `functional_rel` |
| `07-sizeclass` | four size classes with LIFO lists and a bump arena | functional |
| `08-boundary` | boundary tags, one doubly linked free list, constant-time coalescing | safe |
| `08t-boundary-textbook` | textbook boundary tags | loader facts only: the safe row needs ghost state or fractional permissions (see `Ladder.BoundaryTextbook`) |

The statements over a whole executable combine the loader facts with these machine theorems;
`Silmaril.Libc.Shapes.Alloc.Defs` explains why the `functional` strength needs ghost state for
allocators whose blocks carry their size in a header.

Rebuild a rung with `bash examples/alloc-ladder/<rung>/build.sh` (GCC 13.3.0, GNU binutils 2.42);
check the pinned modules with `bash examples/alloc-ladder/pin.sh --check`.

Build: `lake build Silmaril.Libc.Shapes.Alloc.Thms Silmaril.Libc.X86Alloc.Ladder.SizeClass.Thms`
(and the other rungs' `Thms`).
