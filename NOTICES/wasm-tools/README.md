# wasm-tools notices and provenance

The `wasm-tools` executable (`tools/wasm-tools`) and its library (`Silmaril/Wasm/Tools`)
reproduce the command line of
[bytecodealliance/wasm-tools](https://github.com/bytecodealliance/wasm-tools) 1.262.0
(tag `v1.262.0`, source archive SHA-256
`8fafe356b7c63e396d6869c41cb78f76104ae342e1543734f10058d4d5df101c`). Upstream is licensed
`Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT` (`Cargo.toml` of that revision). The
three license texts of that revision are kept here unchanged:
[LICENSE-Apache-2.0_WITH_LLVM-exception](LICENSE-Apache-2.0_WITH_LLVM-exception),
[LICENSE-APACHE](LICENSE-APACHE) and [LICENSE-MIT](LICENSE-MIT).

**Licence option.** The material transcribed or derived from wasm-tools 1.262.0 (the help
texts, completion scripts, operator tables, recorded outputs, known-difference lists such as
`tools/wasm-tools/tests/known-diffs.txt`, and the Lean reimplementations listed below) is used
under the **MIT** option of `Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT`; the MIT
text is [LICENSE-MIT](LICENSE-MIT). This file is the record of that choice: the individual
files carry no licence headers.

No Rust source of wasm-tools is bundled. The upstream binary and source archive are
optional test oracles. The test scripts download them by URL and check them against the
SHA-256 sums in `tools/wasm-tools/tests/pins.sh`.

to produce the same output. The source headers name the crate, and often the file, being
followed. Message strings and output formats are reproduced exactly; the algorithms are
rewritten in Lean.

## Component tools

The component half of the release follows the same wasm-tools 1.262.0 crates, under the same
**MIT** option:

| Included Lean files | Upstream crate |
| --- | --- |
| `Silmaril/Cli/Spec/WasmTools/**` (help texts, usage errors, the generated reference) | `wasm-tools` 1.262.0 command line (clap 4.6 output of its argument definitions) |
| `Silmaril/Wasm/Component/**`, `Silmaril/Wasm/Tools/Component/**` | `wasmparser` (component validation and binary format), `wasm-encoder`, `wit-component` |
| `Silmaril/Wasm/Wit/**` | `wit-parser`, `wit-component`, `wit-smith` |
| `Silmaril/Wasm/Tools/Gen/**` | `wasm-smith`, `wasm-mutate`, `wasm-shrink`, `wit-smith` (behaviour and flags only) |
| `tools/wasm-tools/tests/{component,compval,gen}/**` | recorded outputs and known-difference lists of the pinned binary |

`wasm-jco` and `wasm-wac` reproduce the command lines and output formats of
[bytecodealliance/jco](https://github.com/bytecodealliance/jco) 1.39.0 and
[bytecodealliance/wac](https://github.com/bytecodealliance/wac) 0.12.0
(`Silmaril/Cli/Spec/{Jco,Wac}`, `Silmaril/Wasm/{Jco,JcoTool,Wac}`, `tools/wasm-jco/tests/**`).
Both are licensed `Apache-2.0 WITH LLVM-exception`; the text is
[LICENSE-Apache-2.0_WITH_LLVM-exception](LICENSE-Apache-2.0_WITH_LLVM-exception). No source of
either is bundled; the test scripts use the pinned releases as optional oracles.

## Test binaries with third-party content

`tools/wasm-tools/tests/corpus` (see its `README.md` and `SHA256SUMS`) vendors twelve small
binaries for the differential suites. Seven of them contain third-party material:

| Included files | Third-party content | Terms |
| --- | --- | --- |
| `wasi-{cli,clocks,io,random}-0.2.12.wasm` | the WIT packages `wasi:{cli,clocks,io,random}@0.2.12`, encoded as components by `wasm-tools component wit … --wasm` from `wit/deps/*.wit` of the crate `wasip2` 1.0.4+wasi-0.2.12 (crates.io, `bytecodealliance/wasi-rs` commit `1edbc7add705b075d28436b26057ca9aa5a5a492`, path `crates/wasip2`) | the crate is `Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT`; its three licence files are byte-identical to the three texts in this directory. | `hello.wasm`, `echo.wasm`, `cat.wasm` | WASI 0.3 command components built with Rust 1.99.1 (target `wasm32-wasip2`, `no_std` with `alloc`, release profile with LTO). and these notices are included; the example sources are not.
