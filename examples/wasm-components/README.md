# Wasm components pilot: binaries, provenance and licenses

The binaries of the Wasm components pilot (`docs/projects/wasm-wasi.md`). Each is registered in
`silmaril/artifacts.toml` by `sil project components add`, with its digests, the shape of its
world in `meta.wasm`, and how it was obtained (a `[[derivation]]`). The values and problems are
in `silmaril/wasm-components/` and `Silmaril/Project/WasmComponents/`.

## Provenance

* **wasmtime v50.0.1** (published 2026-10-29), tag commit
  `c307ec81de02852d815e9849f7c89d955c03c30d`; the adapters are built from
  `crates/wasi-preview1-component-adapter`. Release asset digests (GitHub's `digest` field,
  rechecked after download):
  * `wasi_snapshot_preview1.reactor.wasm`
    `6d52112df28f0caee9018f911f279f94f848230b2f0ed02138290363e925671f`
  * `wasi_snapshot_preview1.command.wasm`
    `0b4fe490390ecc9c2222f969f65b179e658a3327e005efd4ddc959766132a3c4`

  The license is the workspace's `license = "Apache-2.0 WITH LLVM-exception"`
  (`Cargo.toml` at the tag); its text is `licenses/wasmtime-LICENSE`, copied from `LICENSE` at
  the tag commit (sha256 `268872b9…f2686bc5`). The adapters' custom section
  `component-type:wit-bindgen:0.62.0:wasi:cli@0.2.12:imports:encoded world` names the world they
  were built against.
* **`wasi:io@0.2.12`**: `wasi.dev/.well-known/wasm-pkg/registry.json` names the OCI registry
  `ghcr.io` with prefix `webassembly/`; the manifest of `webassembly/wasi/io:0.2.12` (digest
  `sha256:bbcae4ac…a671bca8fbc5df4d`) has one `application/wasm` layer,
  `sha256:910ed36e3589ab4c16c9942528152b80485e659852297916313318da47b44af8`, 15183 B, and the
  annotations `licenses = Apache-2.0 WITH LLVM-exception`,
  `source = https://github.com/webassembly/wasi`. The WASI repository's own `LICENSE.md` refers
  to the W3C Community Contributor License Agreement; we rely on the publisher's SPDX annotation.
* **Silmaril-generated**: `lake env lean examples/wasm-components/gen/Gen.lean`
  (Lean `nightly-2026-10-30`) rewrites `lean/{producer,comp-b,linked}.wasm`;
  `RECEIPTS.sha256` lists their digests, and `Silmaril.Project.WasmComponents.Thms` proves that the
  committed components and worlds parse to the Lean ASTs (certificates `gen.*.is`, from
  `Binary.encode`). The worlds are
  `wasm-wit project lean/X.wasm -o lean/X.world.wasm` (recorded by `sil project components add
  --wasm-wit`).
* **The toy**: `lake env lean examples/wasm-components/gen/Toy.lean` (Lean `nightly-2026-10-30`)
  writes `lean/toy.wasm` and
  `lean/toy-split.wasm`; run twice with identical output (`gen/RECEIPTS-toy.sha256`). Its core
  module is `CompToy.toyCore` as encoded by `Binaryen.Exe.encodeModule?`. Registered with
  `sil project components add examples/wasm-components/lean/toy.wasm --license
  LicenseRef-silmaril-lean --name silmaril.wasm_components.gen.toy --wasm-wit .lake/build/bin/wasm-wit`
  (likewise `toy-split.wasm`, whose world file is byte-identical, so its world artifact was
  dropped). The values are certificates in `Silmaril.Project.WasmComponents.Toy.Thms`; the
  derivation `silmaril.wasm_components.gen.toy.recipe` was added by hand, then `sil project lock`.
* **WAC**: `lake env lean examples/wasm-components/wac/Gen.lean` writes `lean/provider.wasm`.
  Then `wac compose wac/pilot.wac --dep silmaril:provider=lean/provider.wasm --dep
  silmaril:comp-b=lean/comp-b.wasm -o wac/pilot.wasm`, with wac-cli 0.12.0 (crates.io; source tag
  `v0.12.0`, `5a7480c69ae7a4dc9eb161f485cbcb8c95e372c9`, as pinned in `docs/projects/wasm-wasi.md`), run
  from this directory or from the repository root with the paths prefixed. Both were run twice
  with identical output (`wac/RECEIPTS.sha256`). `sil project components add … --wac` records
  the composition and its `link` derivation (`docs/projects/wasm-wasi.md`, "WAC compositions").
* `gen/reencode.sh` re-encodes the published `wasi:io@0.2.12` with `wasm-wit encode` and checks
  that the result is the `tests/wat` fixture byte for byte (`RECEIPTS-reencode.sha256`).

## Commands

From the repository root (`M=tools/mor/target/debug/mor`, or `bin/mor`):

```sh
U=https://github.com/bytecodealliance/wasmtime/releases/download/v50.0.1
R=silmaril/wasm-components/values.toml
$M project components add examples/wasm-components/adapter/wasi_snapshot_preview1.reactor.wasm \
  --url $U/wasi_snapshot_preview1.reactor.wasm \
  --sha256 6d52112df28f0caee9018f911f279f94f848230b2f0ed02138290363e925671f \
  --license "Apache-2.0 WITH LLVM-exception" --name silmaril.wasm_components.adapter.reactor --records $R
# … the command adapter likewise
$M project components add wasi:io@0.2.12 --out examples/wasm-components/components/wasi/io-0.2.12.wasm \
  --name silmaril.wasm_components.wasi.io.v0_2_12.oci --records $R
$M project components add wasi:io@0.2.6 --out examples/wasm-components/components/wasi/io-0.2.6.wasm \
  --name silmaril.wasm_components.wasi.io.v0_2_6.oci --format wit.binary --records silmaril/wasm-components/versions.toml
$M project components add tests/wat/fixtures/wasi-io-0.2.12.wasm --release wasi:io@0.2.12 \
  --license "Apache-2.0 WITH LLVM-exception" --name silmaril.wasm_components.wasi.io.v0_2_12.fixture --records $R
$M project components add examples/wasm-components/lean/comp-b.wasm --license LicenseRef-silmaril-lean \
  --name silmaril.wasm_components.gen.comp_b --records $R --wasm-wit .lake/build/bin/wasm-wit
$M project components check
```

The values were then given their formats by hand (`wasm.module.core3`, `wasm.module.world`,
`wasm.component.binary`, `wit.binary`), and the Silmaril-generated components became certificates
(`@[value]` in `Silmaril.Project.WasmComponents.Thms`). `gen.run` was registered with
`sil project components add examples/project-formats/component-run.wasm --no-value
--license LicenseRef-silmaril-lean --name silmaril.wasm_components.gen.run`. The derivations
`silmaril.wasm_components.gen.recipe`, `silmaril.wasm_components.gen.run.recipe` and
`silmaril.wasm_components.wasi.io.v0_2_12.reencode` were added to the registry by hand, then
`sil project lock`. With the files present, `add` needs no network: a file whose sha256 is the
recorded one is used as it is (`--offline` refuses to fetch).
